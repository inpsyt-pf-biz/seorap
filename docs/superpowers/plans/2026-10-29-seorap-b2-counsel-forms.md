## 왜 이 조각인가

상담 상품을 산 구매자는 검사 전에 신청서를 내야 한다(선 상담). 지금 서랍에는 잠금 표시만 있고, [신청서 쓰기]를 눌러도 아무 일도 없다.
신청서는 상품마다 문항이 다르므로(협찬·커플 전용 문항), 상담 어드민에서 템플릿으로 관리하고 상품에 연결한다.

## 어디서 작업하나

|---|---|---|

## 만드는 것 ①: 상담 어드민

| # | 무엇 | 동작 |
|---|---|---|
| A1 | **메뉴 "신청서"** | 왼쪽 메뉴에 추가. 목록: 템플릿 이름, 최신 판, 연결된 상품 수, 상태(초안·게시) |
| A2 | **템플릿 편집** | 머리말, 문항 추가·위아래 이동·삭제. 문항: 유형 9가지(동의·안내문·섹션·단답·장문·객관식·체크박스·날짜·가능 시간대), 질문, 설명, 필수, 선택지, 민감정보 표시, 기존 칸 연결. 저장은 초안 |
| A3 | **미리보기·게시** | 오른쪽에 서랍과 같은 화면 부품으로 미리보기. [게시]하면 새 판(이전 판은 그대로 남음) |
| A4 | **상품 연결** | 관리코드 → 템플릿 + 구매 구분(상담 메인·협찬 등) + 순서. 순서는 "선 상담"만, "선 검사"는 "준비 중"으로 표시만 |
| A5 | **신청서 탭 보강** | 구매 건 상세의 신청서 탭에 "추가 답변"(기존 칸에 연결되지 않은 답)과 "템플릿·판"을 함께 보인다 |
| A6 | **서랍 연결 통로** | 서랍만 부를 수 있는 DB 함수 2개: 상품의 게시된 신청서 가져오기, 제출된 신청서 받기(같은 주문으로 두 번 와도 한 번만) |

- 편집·게시·상품 연결은 관리자만(새 권한 `form.manage`), 담당자는 보기만
- 시드에 현재 Google 신청서("[협찬] STS 커플상담")를 템플릿으로 넣어, 처음부터 실물로 확인할 수 있게 한다

## 만드는 것 ②: 서랍

| # | 무엇 | 동작 |
|---|---|---|
| S1 | **상담 카드** | 상담 상품이 든 서랍 맨 위에 "상담 신청서를 써 주세요 [신청서 쓰기]". 잠긴 검사 줄의 [신청서 쓰기]도 같은 곳으로 |
| S2 | **신청서 화면** `/box/counsel/:주문` | 그 상품에 연결된 템플릿의 게시된 최신 판으로 그린다. 필수·형식은 화면과 서버가 같은 규칙으로 검사 |
| S3 | **가능 시간대 문항** | 요일(평일·토·일) × 시간대(오전·오후·저녁) 눌러 고르기, 가능 시작일(선택) |
| S4 | **제출** | 최근 30분 안에 PIN·OTP로 들어온 세션만. 제출하면 상담 원장으로 넘기고 그 주문의 검사 잠금을 푼다. 서랍에는 제출 시각·템플릿·판만 남긴다 |
| S5 | **제출 후** | 카드가 "제출 완료 · 상담센터가 영업일 7일 안에 연락드려요"로. 제출 내용은 다시 보이지 않는다 |

## 이번에 넣지 않는 것

- "선 검사" 순서와 응시 완료 판정, 주문이 들어올 때 자동으로 잠그는 동작(연동 조각)
- 센터 후보 일시 제안(하지 않기로 함), 제출 후 신청서 수정
- 서랍과 상담 어드민 DB 합치기(사수 탑재 작업). 지금은 연결 통로로 서로 부른다

## 건우님이 눈으로 확인할 것

**상담 어드민** (관리자 계정)
- A. "신청서" 메뉴에 시드 템플릿이 보이고, 문항을 고치고 순서를 바꾸기가 쉬운가
- B. 미리보기가 서랍 화면과 같아 보이는가, 게시하면 판이 올라가는가
- C. 상품 연결 화면에서 관리코드에 템플릿을 붙이기가 헷갈리지 않는가

**서랍** (S2 김철수 · 검사 + 상담 주문)
- D. 맨 위 상담 카드와 잠긴 검사 줄이 자연스러운가
- E. 신청서 화면이 휴대폰에서 쓰기 편한가, 특히 가능 시간대 고르기
- F. 제출하면 검사 줄이 풀리고 카드가 "제출 완료"로 바뀌는가
- G. 상담 어드민의 그 구매 건 신청서 탭에 답이 제대로 들어와 있는가(기존 칸 + 추가 답변, 민감정보는 따로)

## Claude가 테스트로 확인할 것

- 게시한 판은 고칠 수 없고, 수정은 언제나 새 판이 된다. 제출에는 판 번호가 남는다
- 관리자가 아니면 편집·게시·연결이 DB에서 거부된다. 연결 통로 함수는 서랍(서버 비밀키)만 부를 수 있다
- 필수 동의·필수 문항이 비면 화면도 서버도 제출을 거부한다
- 남의 주문, 상담이 없는 주문, 연결된 템플릿이 없는 상품으로는 신청서를 열거나 낼 수 없다
- 같은 주문으로 두 번 제출해도 원장에는 한 건, 잠금 해제도 한 번
- 원장 전달이 실패하면 잠금을 풀지 않는다(답이 사라진 채 검사만 열리지 않게)
- 서랍 DB·응답·로그에 신청서 답 원문이 없다. 민감정보 문항의 답은 원장의 민감정보 표로만 간다

## 순서

1. 공용 모듈: 문항 정의·답 검사·가능 시간대 요약 (서랍 `_shared/core`, 두 앱이 같이 씀) + 단위 테스트
2. 상담 어드민 DB: 템플릿·판·상품 연결·추가 답변 표, 권한, 연결 통로 함수 2개 + DB 테스트, 시드 템플릿
3. 상담 어드민 화면: 목록 → 편집·미리보기·게시 → 상품 연결 → 신청서 탭 보강
4. 서랍: 연결 통로(어댑터)·신청서 서버 함수·잠금 해제 + 테스트
5. 서랍 화면: 상담 카드 → 신청서 화면(가능 시간대 포함) → 제출 후
6. 두 앱을 함께 띄워 처음부터 끝까지 점검 → **건우님 검수(A~G)**
7. 결정 로그·설계 문서에 검수 중 바뀐 점 기록
