## 왜 이 조각인가

1. 진단에서 나온 **바닥 규칙 위반 5건**(칩 색·대비, 포커스, 카드 안의 카드, 점 이음 문자열)을 없앤다.
2. 확정한 **색 ①·로고 C1·리디바탕**을 화면에 처음 입힌다. 원칙은 "닫힌 서랍은 고요하게, 열린 서랍은 따뜻하게".
3. 화면 구성과 동작(링크·버튼·API 호출·문구 키)은 그대로 둔다. 바꾸는 것은 테마와 스타일, 몇 개의 문구뿐이다.

## 만드는 것

| # | 무엇 | 동작 |
|---|---|---|
| 1 | **테마 토큰 교체** `theme/seorap.ts` | 주 색 청록 #1E5552, 쪽 배경 종이 #F6F2EA, 카드 흰색, 글자 #22201C·#6E675C, 상태 색 4종(중립·청록·호박·주의)을 토큰으로. 남색·로고 파랑·MUI 기본 info/warning 은 쓰지 않는다 |

| 3 | **포커스 표시** | 모든 버튼·탭·칩에 키보드 포커스 링(청록 2px, 바깥 2px 띄움)을 테마에서 한 번에 |

| 5 | **글꼴** | 제목(h4~h6)만 리디바탕, 본문·버튼·숫자·코드는 Pretendard 유지. 리디바탕은 완성형 2,350자 + 영숫자로 줄인 woff2 를 직접 둔다(목표 400KB 이하) |
| 6 | **닫힌 서랍 화면** | 진입(인증번호·비밀번호)과 비밀번호 설정 화면은 청록 바탕에 종이색 글자·버튼. 서랍 안(내 검사·전달 이력·신청서·받는 분)은 종이 바탕 |
| 7 | **줄 카드** `LineRow` | 칩은 토큰 색으로 직접 칠한다. 전달 상태는 호박빛 칩 "김영희님께 전달". "→ 이름 · 번호" 대신 "받는 분 김영희 010-…" 두 칸. 줄 버튼은 옅은 청록 채움(주 행동) + 테두리(보조)로, 진한 채움 버튼은 화면당 하나(상담 신청서 작성, 시트의 다음 등)만 |

| 9 | **상담 잠김 줄** | 칩은 짧게 "대기 중", 설명 "상담 신청서를 제출하면 열려요"는 칩 아래 한 줄로. 꺼진 버튼은 B2 결정대로 유지 |
| 10 | **전달 이력** `HistoryPage` | 내 검사 탭과 같은 머리글(이름·로그아웃). 한 건을 "받는 분 + 번호 / 결과 칩 / 시각·검사명" 세 줄로 나눈다 |
| 11 | **코드 보기 창** | 코드를 크게(고정폭 글꼴) 보이고 [코드 복사]를 주 버튼으로, [닫기]는 글자 버튼으로. 복사하면 "복사했어요" 알림 |
| 12 | **상담 신청서 작은 결함** | "필수/선택" 표시가 줄바꿈되지 않게, 제목이 이미 "(선택)"으로 끝나면 표시를 생략, 가능 시간대 칸은 고른 칸에 "가능" 표시 |

## 이번에 넣지 않는 것

- 날짜 칸의 `년-월-일 ()` 표기: 브라우저 기본 날짜 입력이라, 날짜 입력 프로젝트(2026-10-27-datepicker-ux)에서 따로 다룬다
- 동의문 상자 안 스크롤(스크롤 속 스크롤): "전문 보기" 펼침은 다음 조각
- 발급 실패 줄("준비 중")의 안내 문장: 운영 기준(언제·어디로)이 정해진 뒤
- 상담 어드민(사수 브랜치) 화면

## 건우님이 눈으로 확인할 것

- A. 진입 화면(청록)에서 서랍 안(종이)으로 들어갈 때 "닫힌 서랍 → 열린 서랍"으로 느껴지는가
- B. 로고·워드마크·파비콘이 휴대폰 폭에서 또렷한가, "인싸이트" 표시로 진짜 서비스라고 믿을 만한가
- C. 리디바탕 제목 + Pretendard 본문 조합이 어색하지 않은가 (굵은 제목이 없어도 위계가 보이는가)
- D. S1 서랍: 줄마다 남색 버튼이 겹치던 것이 정리됐는가, 전달 줄의 호박빛 칩이 자연스러운가
- E. S2 서랍: 상담 카드 → 잠긴 줄의 "대기 중"과 설명이 한 번만 말하는가
- F. 코드 보기 → [코드 복사]가 휴대폰에서 되는가 (미리보기 배포 후 카카오톡 인앱 브라우저 포함)
- G. 전달 이력이 훑기 쉬운가

## Claude가 테스트로 확인할 것 (화면에 안 보이는 규칙)

- 글자·칩·버튼 색 조합의 명도 대비가 모두 4.5:1 이상이다(테마 시험에서 계산)
- 화면 코드에 색 값·`borderRadius` 숫자를 직접 쓰지 않는다(기존 시험에 반경 규칙 추가)
- 버튼·탭에 포커스 링 스타일이 있다
- 줄 상태: 전달함은 호박 톤 + "김영희님께 전달", 상담 잠김은 "대기 중" + 설명 한 줄(서버 공용 규칙 시험)
- 코드 복사 버튼이 클립보드에 코드를 쓰고 알림을 띄운다, 복사에 실패하면 코드가 선택된 채 남는다
- 화면 코드에 직접 쓴 문장이 없다(새 문구는 모두 문구 사전)
- 리디바탕 서브셋 파일이 400KB 이하이고, 문구 사전의 모든 글자를 담고 있다

## 순서

1. 테마 토큰·반경·포커스 + 시험 (대비 계산 시험 먼저)
2. 로고·워드마크·파비콘, 리디바탕 서브셋과 제목 글꼴
3. 줄 상태 공용 규칙(호박 톤, 대기 중) + 서버 시험 → 줄 카드·주문 묶음·요약
4. 닫힌 서랍 화면(진입·비밀번호 설정)
5. 전달 이력 머리글·한 건 배치, 코드 보기 창
6. 상담 신청서 작은 결함
7. 진단 때와 같은 시드 7개 시나리오를 다시 캡처해 **전후 비교표**를 만들고 Hallmark 린터 재실행 → **건우님 로컬 검수**
8. 피드백 반영 → `feat/plan-a` 위로 다시 쌓아(그사이 B2 커밋 반영) 미리보기 배포 → 휴대폰 검수(F)
9. 웹 게시(운영) 전 리디 글꼴 라이선스 원문 확인. 결정 로그·진단 문서에 결과 기록
