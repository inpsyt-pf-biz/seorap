# 시안 가정 (MVP-0 ~ MVP-1)

시안은 아래 기본값으로 만들었습니다. 답이 다르면 "바뀌는 곳"만 고칩니다.

| # | 가정 | 기본값 | 다르면 바뀌는 곳 |
|---|---|---|---|
| M1 | 센터 전문 분야(구 카테고리) | 발달 · 정서 · 청소년 · 학습 · 가족 (5종, 여러 개 선택). 대상의 "아동·청소년"과 전문 분야의 "청소년"은 다른 축이다 | 마이그레이션 CHECK, `core/centers.ts`, `core/copy.ko.ts`, 태그 색(`web/src/theme/admin.ts`). `core/centers.test.ts`가 DB와 화면 목록을 대조 |
| M2 | 센터 상태 | 입점 준비 · 운영 중 · 신규 배정 중지 · 계약 종료 (4종). 목록에서는 운영 중이 아닌 센터만 이름 아래에 표시 | 같음 |
| M3 | 목록의 "지역" | 센터가 있는 곳 1군데(시·도 + 구·시, 예: 서울 강남). 구·시는 직접 입력 | 구·시를 목록에서 고르게 하려면 행정구역 목록 추가 |
| M4 | 상담 가능 지역 | 시·도 여러 개. 목록에는 안 보이고 상세·수정 화면에만 있다. 예약을 센터에 배정할 때 쓴다 | - |
| M5 | 상담 완료/배정 | 상담 장부에서 센다. 배정은 취소를 뺀 건수, 완료는 상담 완료 건수(MVP-1부터) | `counsel.center_stats` 뷰 |
| M6 | 센터는 지우지 않는다 | 끝난 센터는 "계약 종료"로 남긴다. 삭제 기능 없음 | 삭제 함수 추가 |
| M7 | 기관명은 겹치지 않는다 | 대소문자를 무시하고 같은 이름 등록을 막는다 | `centers_name_unique` 인덱스 |
| M8 | 연락처 형식 | 숫자와 `-`로 8~20자. 대표번호는 유선·070도 받고, 휴대폰 형식으로 바꾸지 않는다 | 마이그레이션 CHECK, `validateCenterInput` |
| M9 | 센터 정보 관리 권한 | 인싸이트 관리자만 등록·수정. 담당자는 보기만 | `counsel.role_caps` 한 줄 |
| M10 | 인싸이트 본사 | 센터 표의 한 행. 목록에 보이지 않고 화면에서 고칠 수 없다 | `listCenters`, `rpc_update_center` |
| M11 | 변경 이력 | 마지막 수정 시각과 version만 남긴다. 누가 무엇을 바꿨는지는 예약 원장(MVP-1)부터 | 이력 표와 트리거 추가 |
| M12 | 담당자 | 센터당 대표 담당자 1명. 여러 명은 센터 직원 레코드(MVP-2)에서 | 센터 직원 표 |
| M13 | 지도 서비스 | 네이버 클라우드 Maps. 시안은 Mind-Connect의 키를 같이 쓴다 | `web/src/lib/naverMaps.ts` 하나만 바꾼다 |
| M14 | 센터 위치 | 등록·수정 화면에서 지도를 눌러 찍는다(주소로 자동으로 찾지 않음). 국내 좌표만 받는다 | 주소 → 좌표 변환을 붙이면 위치 찍기를 자동으로 채운다 |
| M15 | 지도 동그라미 | 전국 화면은 시·도별 센터 수(소재지 기준). 동그라미 자리는 겹치지 않게 정한 표시용 자리다. 확대 10단계부터 센터별 핀 | `core/geo.ts` 의 `SIDO_ANCHORS`, `PIN_ZOOM` |
| M16 | 센터 대상 | 영유아 · 아동·청소년 · 성인 (여러 개 선택). 기획 문서 Step 1 필터의 "상담 유형" | 마이그레이션 CHECK, `core/centers.ts` |
| M17 | 운영 시간 | 자유 입력 한 줄(100자). 예약 가능 시간을 시스템이 판단하지 않으므로 요일별 칸으로 나누지 않는다 | 요일별 구조로 바꾸려면 칸 추가 |

## MVP-1 (구매 건 · 배정)

| # | 가정 | 기본값 | 다르면 바뀌는 곳 |
|---|---|---|---|
| M18 | 구매 구분 | 검사 메인 · 상담 메인 · 협찬 · 공동구매 (현행 구글폼 신청서 4종) | 마이그레이션 CHECK, `core/purchases.ts` |
| M19 | 상담 상태 | 미배정 → 예약 요청 → 예약 확정 → 상담 완료, 이탈은 상담 불가 · 취소. "예약 요청"은 센터에 배정되어 예약을 기다리는 상태 | 같음 |
| M20 | 배정·다시 배정 | 미배정·예약 요청 상태만 바꾼다. 예약 확정 이후 건은 건너뛴다(상태 되돌리기는 MVP-2) | `rpc_assign_sessions`, `ASSIGNABLE_STATUSES` |
| M21 | 배정할 수 있는 센터 | 운영 중인 센터만. 입점 준비·신규 배정 중지·계약 종료 센터와 본사는 DB가 거부 | `rpc_assign_sessions` |
| M22 | 구매 1건의 상담 횟수 | 1회. 표에는 회차(`seq`) 칸이 있어 여러 회로 늘릴 수 있다 | 등록·가져오기 함수가 만드는 상담 줄 수 |
| M23 | 민감정보·마케팅 정보 | 복용 약물·진단명, 결과지 링크는 `application_sensitive`, 알게 된 경위는 `application_marketing`에 따로 둔다. 지금은 본사만 읽는다. 센터 계정이 생기면 민감정보는 배정된 센터만, 마케팅은 본사만 | 두 표의 행 단위 권한 |
| M24 | 시트에서 같은 줄 판정 | 신청서 종류 + 응답 시각 + 연락처 + 이름이 같으면 같은 줄. 다시 가져와도 한 건만 남는다 | `core/sheetImport.ts`의 `source_key` |
| M25 | 시트의 담당자 칸 | 예약전화 완료 체크·상담 예약 일정·관리자 메모는 관리자 메모에 붙인다. 가져온 건은 모두 미배정으로 시작한다 | `toImportRow` |
| M26 | "상담 종료" 체크된 줄 | 기본으로 건너뛴다(가져오기 창에서 끌 수 있다) | 가져오기 창 체크 상자 |
| M27 | 검사 실시 칸 | 서랍 연결(Step 0) 전까지 "서랍 연결 후"로 표시 | 서랍 검사 진행 상태를 읽어 채운다 |
| M28 | 신청서 날짜 | 폼 응답 시각. 직접 등록해서 응답 시각이 없으면 등록한 날 | 목록 "신청서" 칸 |
| M29 | 상태별 건수 칩 | 검색·구분·센터·검사 거르기를 적용한 결과로 센다. 칩을 눌러도 다른 칩 숫자는 그대로 | `PurchasesListPage` |
